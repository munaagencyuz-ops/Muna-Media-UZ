## Capture semantics and operational limits

- The `LeadDelivery` SQLite Durable Object persists receipt metadata only: random nonce/receipt, keyed payload digest, fixed provider/chunk states, bounded acknowledgement IDs and timestamps. No raw name, phone, address, email, task, IP or provider error body is persisted or logged by this receiver.
- `stored:true` denotes durable receipt metadata plus acknowledged provider submissions, not a complete enquiry database or a person's read confirmation. Lead text resides in the owner-selected Telegram/mail destinations.
- UUID idempotency key is retained only in browser RAM for an unchanged pending payload. Matched retries skip acknowledged channels/chunks. Payload reuse under another body is rejected.
- Pre-send fences, timeouts/lost acknowledgements and recovered unresolved attempts become unknown and are not automatically resent. No exactly-once guarantee or background payload outbox is claimed.
- Metadata dedupe/retention window: seven days from first attempt, with alarm and access-time cleanup. Provider/mailbox copies are outside this cleanup. Reload/tab closure loses pending browser nonce associations; do not submit a new enquiry to work around an unknown outcome.
- Streaming body/type/origin/field limits, native wrapper rate-limit decisions, HTML escaping, fixed destination restrictions, bounded provider calls and source/CMS protections remain enabled.

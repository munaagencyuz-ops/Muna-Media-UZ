# Release checkpoint — 28 October 2026

Target: **https://munamedia.uz/**. Audience: local businesses in Uzbekistan. `munaagency.com` is outside this release and was not modified.

## Shipped implementation

- Uzbek-first navigation, services, contact journeys and metadata; Russian pages at `/ru/`.
- Official-source directory of 120 cities, with 14 distinct planning guides. This is not a claim of offices or pre-confirmed inventory in every city.
- 74 sitemap URLs; historical case sources retained.
- All eight bundles rebuilt. Dependency audit: zero advisories after lockfile updates.
- Reviewed unsupported current Uzbek infrastructure availability value replaced with `Kelishiladi`; Russian archival/source wording retained.

## Production architecture

- Marketing Worker: `muna-media-uz-site`; version `37f75077-7b90-4f7e-9fde-1b31bd133eea`.
- Build/deploy: `npm ci --ignore-scripts`, `npm run deploy`.
- `worker.entry.mjs` wraps compiled Pages Functions, supplies security headers and API rate limiting.
- `scripts/prepare-worker-assets.cjs` isolates public assets. CMS files, source/control files and source maps are excluded from the marketing asset upload.
- Worker public URLs and previews are disabled. Existing Pages project and its secrets were not overwritten.
- Marketing routes are managed separately in Cloudflare: `munamedia.uz/*` and `www.munamedia.uz/*` target this Worker. Six more-specific `/cms*`, `/studio*`, `/admin*` routes on both hosts have **no Worker script**, preserving the private original origin.
- Do not remove these private exclusions, disable All Workers, expose `pages.dev`, or attach public bypass to shared internal applications.
- `deploy:pages` retains the historical Pages workflow; it is **not** the active marketing release workflow.

## Explicit unfinished external gates

- `www.munamedia.uz` still reaches Cloudflare Access instead of its intended canonical redirect, despite exact Worker/DNS configuration. Apex marketing pages are public. Do not report www as repaired.
- Online capture has no approved private receiver. It fails closed; a visible notice points to the established `info@munamedia.me` and `https://t.me/munamedia`. No real lead/provider POST was used in acceptance.
- Existing Sanity secret bindings remain on Pages; they were not readable/transferred. Live CMS content integration and authenticated editorial access are not certified by the public-page checks.

## Rollback

Remove only the two marketing Worker routes to return these hostnames to the original Pages origin. This also restores the previous Access-blocked public behavior. Preserve the six private route exclusions and all existing Access policies/Pages secrets. No DNS/mail/Access changes to `munaagency.com` are part of this release.
